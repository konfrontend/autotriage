!`node ${CLAUDE_PLUGIN_ROOT}/scripts/guard.mjs triage $ARGUMENTS`

Judgment is the model's, arithmetic is the script's (ADR 0002). This State reads the Job and the Profile, detects Flags, scores fit, picks the Family, and writes ids and numbers into the `verdict` block of `job.md`. `node ${CLAUDE_PLUGIN_ROOT}/scripts/verdict.mjs` then computes `alert_level`, `hard_stops`, and `verdict` from them; the `proposal` guard recomputes and rejects a block that disagrees, so the computed fields are never typed by hand. Everything else this State produces (evidence quotes, reasons, matched cues, mitigations) is printed for the human and thrown away; the Candidate keeps only the block. The one other artifact this State writes is the Skill ledger `data/profile/skills.md`: every triage run, whatever the decision, records which of its rows the Job required and adds a Gap row for a required item the Profile has no row for (ADR 0003).

Inputs: `data/candidates/$ARGUMENTS/job.md` (frontmatter fields plus the posting verbatim in the body, parameter line included), `data/profile/profile.md` (`refused_stacks`, `identity.constraints`, `niche`, `interests`, `avoid`, `family_precedence`, `terms`), the Skill ledger `data/profile/skills.md` (rows with `name`, `level`, `evidence`, `keywords`, `seen`), the ledger catalogue `${CLAUDE_PLUGIN_ROOT}/catalogue/skills.md` (Level tests, matching rules), the Flag catalogue `${CLAUDE_PLUGIN_ROOT}/catalogue/flags.md` (Flags with cues, `scores` rubrics, `alert_level_steps`, `hard_stops`, `verdict_mapping`, the checkpoint print order), and the Family catalogue `${CLAUDE_PLUGIN_ROOT}/catalogue/families.md` (Families with cues, tie rule). Read all six before step 1; the catalogues are the rules, this file is the procedure.

## Steps

1. **Flags.** Walk the whole Job, parameter line and screening questions included, against every Flag in the catalogue. A Flag triggers on the meaning of the cues, not on their wording: postings paraphrase. Per triggered Flag hold its id, its level, and one verbatim quote from the Job as evidence; for a stop Flag also the Profile entry it collides with (`refused_stacks`, `identity.constraints`). Green Flags in the same pass. A required stack item is one the Job names as the codebase or a must, not a nice-to-have in a preferred list. Done when every Flag in the catalogue has been judged and each triggered one has a quote.
2. **Scores.** Judge `skill_fit`, `interest_fit`, `value` against the `scores` rubrics, one line of reason each, naming the Profile entries it rests on. `skill_fit`: list the Job's required items by the matching rules of the ledger catalogue (the one place those rules live) and run `node ${CLAUDE_PLUGIN_ROOT}/scripts/skills.mjs match "<item>" ...` with every item; the script names the rows each item matches by name or keyword. Confirm or correct the list by reading: an item the rule caught wrongly is dropped, a row it missed is added, and an item with no row is a new Gap with a `category` chosen from the ledger enum. Mark each item by its row's Level (`shipped`, `used`, `learning`, `gap`, or no row). Hold the table: item, matched rows, Level. `interest_fit`: `niche`, `interests`, `avoid`. `value`: Profile `family_precedence` position of the Family from step 3 plus contract size estimated from budget, hours, and duration at Profile `terms.rate`. Done when the three integers each have a rubric line they match.
3. **Family.** Pick `family` and `family_runner_up` from the Family catalogue cues, triggered Flags first; the tie rule is the Profile's `family_precedence`. Hold the matched cues and a confidence word (`clear`, `leaning`, `guess`) for the summary. Nothing fits: `family: null`, runner-up `null`. Done when both fields hold a Family id or `null`.
4. **Write the block.** With the Edit tool, add the `verdict` block as the last key of the `job.md` frontmatter, replacing an existing one: `family`, `family_runner_up`, `flags` (every triggered id, green and stop included), `skill_fit`, `interest_fit`, `value`, then the placeholders `alert_level: 1`, `hard_stops: []`, `verdict: ask`, `decision: null`. The write hook validates against `${CLAUDE_PLUGIN_ROOT}/scripts/schemas/job.schema.json` and blocks with the error list on mismatch: fix and write again. Then run `node ${CLAUDE_PLUGIN_ROOT}/scripts/verdict.mjs $ARGUMENTS`; it rewrites the three computed fields and prints them. Done when the script has printed `alert_level`, `hard_stops`, `verdict`.
5. **Summary.** Print one screen in the order the Flag catalogue fixes under "What the human sees first": the verdict line (verdict, Alert Level, Family with runner-up and confidence, three scores), hard stops, each triggered Flag as `id (level N): "quote"`, green Flags, the mitigations the Letter will state (the `mitigation` of every triggered risk Flag whose mitigation is not `none`, with its `slot`), a "Skills table changes" block (one line per Job item as `item -> row (level)` or `item -> new gap row (category)`, then the Seen appends and the new Gap rows the ledger will receive), and one closing line: why `ask`, or why not the neighbouring verdict. Add the posted budget against the Profile rate when the Job is `fixed` or hourly below `terms.rate`, so the human sees the money before answering. Done when every triggered Flag and every hard stop appears on the screen.
6. **Checkpoint.** Ask the human for `go` or `no-go` and wait. A correction instead (a Flag to add or drop, a score, the Family, a row in the Skills table changes block): apply it, redo steps 4 and 5, ask again. Write the answer into `verdict.decision` with the Edit tool. Then record the confirmed block into the ledger, on `go` and on `no-go` alike: `node ${CLAUDE_PLUGIN_ROOT}/scripts/skills.mjs record $ARGUMENTS --seen "<row name>" ... --gap "<name>:<category>" ...`, one `--seen` per matched row and one `--gap` per new Gap row; it appends the Candidate to each row's `seen` once, adds the Gap rows, validates, and prints what changed. Done when `decision` is `go` or `no-go` and the script has printed its changes.
7. **Hand off.** On `go`: invoke `autotriage:proposal $ARGUMENTS` with the Skill tool, no further question. On `no-go`: one line saying the Route has ended for this Candidate.
