# autotriage

## Agent skills

### Issue tracker

GitHub Issues of `konfrontend/autotriage`, via the `gh` CLI. See `docs/agents/issue-tracker.md`.

### Triage labels

Default five labels (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`), applied as GitHub issue labels (already exist in the repo). See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: `CONTEXT.md` + `docs/adr/` at the repo root. See `docs/agents/domain.md`.

## Plugin layout

The repo root is the Claude Code plugin and its own marketplace (`.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, marketplace `konfrontend`). `skills/<category>/<skill>/SKILL.md`, every skill listed in `plugin.json`: `route/` holds `route` (entry) and one skill per State, `profile/` holds `setup` and `skills`. `catalogue/` holds the portable Families, Flags, voice, verify Checks, Letter templates, the Candidate artifact contract, and the Skill ledger rules; `scripts/` the Guard, the Verdict arithmetic, the hooks, `schemas/`, and `vendor/deps.mjs` (generated by `npm run vendor`, never edited by hand); `hooks/hooks.json` registers the hooks.

The repo holds no user data. The Profile and the Candidates live in `data/` of the project that installs the plugin (ADR 0004). Develop against such a project with `claude --plugin-dir <this repo>`. Bump `version` in `plugin.json` on every release, or installed copies do not update.
